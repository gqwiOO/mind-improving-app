# Мій куточок

Персональний сайт на [Astro](https://astro.build): пости, книги, замітки.
Без бази даних, без аналітики — увесь контент живе у текстових файлах.

## Запуск

```bash
npm install      # один раз
npm run dev      # сайт: http://localhost:4321
                 # адмінка: http://localhost:4321/admin
```

Інші команди:

| Команда | Що робить |
| --- | --- |
| `npm run build` | збирає готовий сайт у `dist/` |
| `npm run preview` | показує зібраний сайт як на продакшені |
| `npm run check` | перевіряє типи й помилки в шаблонах |

## Редагування

Є три способи, і всі вони працюють з тими самими файлами — можна вільно
змішувати.

### 1. Адмінка (найпростіше)

Запусти `npm run dev` і відкрий **http://localhost:4321/admin**.

Списки, форми, редактор з панеллю інструментів і передпереглядом, кнопка
«Видалити». Зміни пишуться прямо у файли проєкту, а сайт у сусідній вкладці
оновлюється сам.

Що варто знати:

- Адмінка живе **тільки** в режимі `npm run dev`. У зібраний сайт вона не
  потрапляє взагалі — ні сторінка, ні API. Опублікований сайт лишається
  звичайною статикою, у якій нічого не можна змінити ззовні.
- Заголовок автоматично перетворюється на адресу за правилами транслітерації
  («Привіт, світе» → `pryvit-svite`). Її видно й можна виправити в полі
  «Адреса» внизу форми.
- Видалення остаточне — файл стирається з диска. Якщо проєкт під git, це
  можна відкотити; якщо ні — ні.

### 2. Просто редактор

Файли звичайні, тож VS Code, Obsidian чи будь-що інше теж підійде. Структура
описана нижче.

### 3. З інтернету (Decap CMS) — треба налаштувати

У `public/cms/` лежить готовий веб-редактор: ті самі шість розділів, доступ з
телефона, зміни їдуть комітами в GitHub. **Він поки не працює** — потрібні
репозиторій і хостинг. Щоб увімкнути:

1. ~~Залити проєкт у репозиторій на GitHub~~ — зроблено:
   [gqwiOO/mind-improving-app](https://github.com/gqwiOO/mind-improving-app).
2. Опублікувати сайт (Cloudflare Pages / Netlify / GitHub Pages).
3. Створити GitHub OAuth App: *Settings → Developer settings → OAuth Apps →
   New*. Callback URL — `https://твій-домен/cms/`.
4. Вписати отриманий Client ID у `app_id` в `public/cms/config.yml`
   (`repo` там уже заповнено).
5. Відкрити `https://твій-домен/cms/`.

Авторизація йде через PKCE, тому власний сервер не потрібен.

## Де що лежить

```
src/
  site.ts                 ← ім'я, опис, навігація, соцмережі
  content.config.ts       ← які поля дозволені в кожному типі контенту
  content/
    posts/*.md            ← пости блогу
    til/*.md              ← короткі замітки
    pages/*.md            ← about, now, uses (і будь-які нові сторінки)
  data/
    books.yaml            ← книги
    projects.yaml         ← проєкти
    links.yaml            ← blogroll
  admin/                  ← локальна адмінка (у зібраний сайт не входить)
  styles/global.css       ← усі стилі, зверху — кольори теми
public/
  cms/                    ← веб-редактор Decap (поки не налаштований)
  avatar.svg, favicon.svg
```

**Почни з `src/site.ts`** — там ім'я, опис і меню.

## Як додати пост

Через адмінку — кнопка «Додати пост». Руками — створи файл
`src/content/posts/nazva-posta.md`. Назва файлу стає адресою:
`nazva-posta.md` → `/writing/nazva-posta`.

```markdown
---
title: Заголовок
date: 2026-08-20
description: Одне речення для головної, RSS і пошуку. Необов'язкове.
tags: [книги, письмо]
draft: false
---

Текст посту.
```

`draft: true` — пост видно тільки в `npm run dev`, у зібраний сайт він не потрапляє.

## Як додати книжку

Через адмінку — розділ «Книги». Руками — допиши блок у список `books:`
у `src/data/books.yaml`:

```yaml
books:
  - id: unikalnyi-rjadok
    title: Назва книжки
    year: 2026
    rating: 4.5
    note: Два речення про те, чим вона була.
    url: https://посилання.куди-завгодно
```

Обов'язкові тільки `id` і `title`. Щоб книжка показувалася в блоці
«зараз читаю» на головній — постав `status: reading` і прибери `year`.

Порядок записів у файлі не має значення: сторінка `/books` сортує їх за роком
сама, як і рахує статистику й будує графік.

Для довгих нотаток зручний YAML-блок `>-`:

```yaml
    note: >-
      Перший рядок нотатки,
      другий рядок — вони склеяться в один абзац.
```

## Як додати замітку (TIL)

`src/content/til/nazva.md`:

```markdown
---
title: Що я дізнався
date: 2026-08-20
tags: [css]
source: https://джерело
---

Два-три речення. Показується повністю прямо в списку на /til.
```

## Як додати нову сторінку

Кинь markdown-файл у `src/content/pages/`. Файл `contact.md` стає сторінкою
`/contact`. Щоб вона з'явилася в меню — додай рядок у `nav` або `footerNav`
у `src/site.ts`.

## Теги і пошук

Теги збираються автоматично з постів і TIL — сторінки `/tags` і
`/tags/назва-тега` створюються самі.

Пошук (`/search`) працює в браузері: покажчик вбудований у сторінку, сервер
не потрібен. На кількох сотнях записів це залишається швидким; якщо колись
стане більше — тоді варто перейти на [Pagefind](https://pagefind.app/).

## Перед публікацією

1. У `astro.config.mjs` заміни `https://example.com` на свій домен —
   від цього залежать посилання в RSS і sitemap.
2. Те саме в `public/robots.txt`.
3. Заміни `public/avatar.svg` і `public/favicon.svg` на свої.
4. Пройдись по `src/site.ts` і `src/content/pages/`.

## Хостинг

Сайт статичний: `npm run build` кладе готові HTML-файли в `dist/`, які можна
залити будь-куди. Найпростіші безкоштовні варіанти — GitHub Pages,
Cloudflare Pages, Netlify. Зараз не налаштовано нічого — тільки локальний
запуск.
